# 旅途手账：照片识别、千问素材与用户页面保护

核对日期：2026-09-29。

## 数据链路

1. 相册照片存放在私有 `MediaStore`。照片分析任务将 VLM 场景、活动、物体、地点线索等标签写入私有照片元数据。用户在旅途页明确选择照片，写入 `selected-photos` 清单。
2. `POST /api/media/trips/{tripId}/journal/compose` 只读取该清单内照片的文字标签及行程地点。它向当前配置的 StepFun 发送精简的场景信息、模板目录和照片 ID。照片字节、原始 EXIF、精确 GPS、OCR 和人物字段不发送给 StepFun。没有识别标签时提示模型只依据已知行程，不编造照片细节。
3. StepFun 选择两页模板、精选照片顺序，写短日记与明信片留言，并提出贴纸、邮票、插画和明信片的具体图案。Web 将这些文字主题分别提交为 Spark Qwen-Image-2.1 文生图任务；工作流从 `EmptyLatentImage` 开始，不上传用户照片。提示词版本存在 `prompts/journal-*.qwen-image-2.1.json`，任务冻结完整工作流、seed 和 prompt UUID。
4. 图片与邮票/贴纸通过私有图片接口读取。照片留在相框内，千问生成的插画与明信片图作为各自的底图，文字、邮票独立叠放，因此用户仍能编辑。

## 页面所有权

`GET /api/media/trips/{tripId}/journal` 返回私有手账及版本号。用户每次修改一个页面，经 `PUT /journal/pages/{pageIndex}` 保存整页，服务器将该页标记 `protected=true, source=user`；用户新增跨页时，两页立即保护。写入需要匹配版本号，避免静默覆盖并发更新。

AI 提案经过 `POST /journal/apply-ai` 写入。服务器只替换未保护页；如果前两页都属于用户，则在页数上限内追加新的 AI 跨页。页面保护在服务器侧执行，前端仅显示状态。重新打开手账仍从私有存储读取这些状态。测试覆盖用户修改、AI 重排、用户新增跨页和进程重启后的不变性。

## 当前限制

- 照片必须先经过选优清单提交，Agent 才会以其识别标签编排照片。未打标签的精选照片只有日期和 ID，不会被描述成有具体画面内容。
- 生成素材的真实质量与可用性仍需在当前 Spark 部署中对四类任务分别验收。当前 Spark 工作目录版本与本仓库主线不同，部署后还需用实际账号、实际任务检查。
- 一趟行程最多 12 页、60 件 Qwen 素材。页面编辑采用服务器版本号；网络中断时前端显示未同步错误，本地浏览器保留布局缓存。
